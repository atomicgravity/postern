## 1. Phase goal

Land the on-device timefix path end-to-end. After this phase, an engineer with a valid timefix cert can recover a device with a broken clock by running a single CLI subcommand; the path is privilege-split per `DESIGN.md`, audited per the broker's existing AuditEvent invariant, and the unwrapped `postern` binary works against a stock device image built from the framework's reference packaging seam.

## 2. Scope

| # | Deliverable | Replaces |
|---|---|---|
| 1 | `cmd/timefix-apply/` — unprivileged on-device JWS verifier. Reads JWS from stdin, generates and emits 32-byte base64url nonce, validates against pinned `alg`+`typ`+CA pubkey+device serial+nonce+`now`-range, execs the setter with a single integer timestamp arg. | net-new binary |
| 2 | `cmd/timefix-set-clock/` — privileged setter, intentionally trivial. Single integer arg (unix seconds), calls `clock_settime(CLOCK_REALTIME, ...)`, then `RTC_SET_TIME` ioctl on `/dev/rtc0`, exits. No stdin read, no file read, no other input surface. | net-new binary |
| 3 | `POST /ssh/time-payload` broker endpoint — full impl replacing the 501 stub mounted in `pkg/brokerhandlers/handlers.go`. Validates IdP access token + Policy (`MintTimefixCert`) + RateLimit + Registry, then signs the JWS Compact-serialized time payload via the existing KMS Ed25519 Signer. Emits `time_payload_issued` / `time_payload_denied` audit events. | the `unimplementedHandler` mounted today |
| 4 | `postern timefix <device-id>` CLI subcommand — replaces the `configPlaceholderCommand` registered in `pkg/cliapp/app.go`. Orchestrates the full flow: open SSH connection to the device's `timefix` principal using the cached timefix cert (or mint one), read the nonce from the device's stdout, POST `/ssh/time-payload` with `{device_id, nonce}` + bearer, pipe the returned JWS to the device's stdin, surface the device's exit code. | the `configPlaceholderCommand("timefix ...")` entry |
| 5 | On-device packaging recipe sample at `examples/on-device/timefix/` — Buildroot/Yocto-agnostic install fragment (binary paths, `setcap` line, user creation, sshd config drop-in cross-reference). | net-new sample |

## 3. Non-goals

- **Yocto / Buildroot integration recipes** — operator integration concern. The packaging sample at `examples/on-device/timefix/` is a documentation reference, not a `bitbake`-runnable layer or a `BR2_PACKAGE_*` declaration.
- **Automatic clock-drift detection on the device** — out of scope. The framework provides a recovery path; deciding when to invoke it is operator policy.
- **NTP, chrony, or PTP integration** — orthogonal. Devices that can sync to NTP don't need this path; this path is for devices that can't (no network at boot, broken battery, sealed-off filesystem).
- **A `timefix-status` or `timefix --dry-run` mode** — not in scope. The verifier exits 0 on success, non-zero on failure with a clear stderr message; that's the surface.
- **`postern upgrade`** — separate v1 gap, separate phase. Mentioned together in `docs/team-handoff.md` §4 only because both are still placeholders; nothing else couples them.
- **Hardening the long-running broker against a malicious device** — the device is the recipient, not a caller. No new attack surface on the broker beyond what `/ssh/cert` already exposes.
- **Smooth slewing via `adjtime`** — see open question OQ-TF-1; the v1 setter shape per `DESIGN.md` §"`/usr/sbin/timefix-set-clock` (Go) — privileged setter" is a hard `clock_settime` step.

| D5 | **Broker-side payload generation: `go-jose/v4` for JWS Compact construction (production), with `internal/signer.KMSSigner` providing the EdDSA signature through a `jose.OpaqueSigner` adapter.** `KMSSigner` currently exposes only `SignCert(ctx, *ssh.Certificate)`; this phase adds a sibling **purpose-specific** signing method `SignTimePayload(ctx, signingInput []byte) ([]byte, error)` on `KMSSigner` and extends the `internal/broker.CertSigner` interface with the same method. Supersedes the prior hand-rolled three-segment serialization shape (LD-79); LD-90 supersedes LD-79 with this decision recorded in the architect log. ## 5. New invariants this phase establishes

(Continuing the A–N sequence carried from archived logs.)

| id | invariant |
|----|-----------|
| O | **Setter input surface is exactly one positional integer arg.** The setter MUST NOT read stdin, MUST NOT read env vars (beyond what the Go runtime needs), MUST NOT read files except the syscall/ioctl targets, MUST NOT accept flags. Widening requires explicit architectural sign-off. |
| P | **Verifier rejects on the first failed check; exit code distinguishes failure classes.** Exit codes are stable wire contract for on-device log analysis: 0 success, 2 bad input (truncated JWS / not-three-segments), 3 alg/typ mismatch, 4 signature verify failure, 5 claim validation failure (aud/device_serial/nonce/now), 6 setter exec failure. Single-pass; no "report all errors" mode. |
| Q | **`time_payload_authorized` emits pre-Sign (fail-closed on emit failure — no Sign if audit can't record the decision); `time_payload_issued` emits post-Sign (best-effort).** Sign failure produces `time_payload_denied` with `denied_reason: signer_failure`. Post-Sign audit failure logs to slog but does not undo the issuance. Joining `authorized` ↔ `issued` on `jti` lets operators detect missed issuances. Same pattern LD-64 established for `ssh_cert_authorized`/`ssh_cert_issued`. |
| R | **Time payload JWS structure is pinned by alg + typ + claim semantics.** Verifier pins `alg=EdDSA` positively via its accepted-algorithm list (no negotiation, no `alg=none` blacklist — the positive pin closes algorithm-confusion). Header `typ` MUST equal `postern-timefix+jwt` (defense against using a token from a different signing context). Signature MUST verify against the on-device CA pubkey. Claim semantics MUST hold (`aud == device-<serial>-timefix`, `device_serial == expected serial`, `nonce == device-issued nonce`, `now` within the half-open `[2024-01-01T00:00:00Z, 2099-01-01T00:00:00Z)` bound per D11). Unknown header fields and unknown payload fields are ignored on both sides (forward-compat headroom; tolerant decode). The broker MUST NOT emit unknown payload fields in v1; tolerant verifier decode is a forward-compat property, not a license to emit. The prior wording's "header has exactly `{alg, typ}` and no kid/jwk/x5c/crit" rule is dropped (with `alg` positively pinned via the accepted-algorithm list, extra header fields cannot widen attacker capability — see post-TF-E correction in `docs/architect-log.md` Notes-section bullet and LD-90/LD-91). `DESIGN.md` §"Device-side validation" is the canonical 7-check list this invariant restates. |
| S | **`KMSSigner` exposes only purpose-specific signing methods (`SignCert` per SSH cert, `SignTimePayload` per JWS time payload). No generic `Sign([]byte)` or `SignRaw([]byte)`.** The `CertSigner` interface in `internal/broker` follows the same rule. Adding a new signing role requires (a) a new purpose-specific method on `KMSSigner` and the interface, (b) an explicit byte-structure-non-overlap analysis showing the new message shape cannot be confused with any existing signed-message shape (the structural argument that protects domain separation under the one-CA invariant). The rule exists because the underlying EdDSA primitive signs raw bytes — domain separation is purely structural, and a generic `Sign([]byte)` advertises "sign anything" which silently breaks the structural argument the first time a future contributor uses it for a message shape that overlaps existing ones. |

Existing invariants this phase relies on (named for reference, not duplicated): the one-CA decision (`DESIGN.md` §"Why one CA and not three"), invariant N (KMS Ed25519 key spec), LD-64 (cert pipeline reorder + audit split), LD-65 (audit-coverage strict invariant).

## 8. Success criteria

A sub-phase TF-E close requires **all** of the following:

1. `make check` green (`go test -race ./...`), no new SKIPs beyond the two pre-existing env-gated keychain/IdP integration tests.
2. The broker handler test for `/ssh/time-payload` produces a JWS that parses back successfully via `go-jose/v4`, validates against the test CA pubkey, and carries all eight payload fields with correct types.
3. The verifier rejects each of these inputs **with a distinct exit code per invariant P**: missing JWS / truncated JWS, wrong `alg`, wrong `typ`, signature mismatch, wrong `aud`, wrong `device_serial`, wrong `nonce`, `now` outside the half-open `[2024-01-01T00:00:00Z, 2099-01-01T00:00:00Z)` bound per D11 (test both endpoints: `2023-12-31T23:59:59Z` rejects, `2099-01-01T00:00:00Z` rejects, `2024-01-01T00:00:00Z` accepts). **No test obligation on "verifier rejects unknown header fields" or "verifier rejects header with extra kid/jwk/x5c/crit"** — those were manufactured-strictness requirements dropped in the LD-90 + LD-91 correction (invariant R rewrite); with `alg=EdDSA` positively pinned via go-jose's accepted-algorithm list, extra header fields cannot widen attacker capability. The alg-pin test exercises the library's accepted-algs rejection (e.g. a JWS signed with `alg=HS256` or `alg=none` MUST be rejected by `jose.ParseSigned` before any signature work), not a hand-rolled `if alg != "EdDSA"` branch.
4. The setter rejects multi-arg input (more than one positional arg → non-zero exit). The setter rejects non-integer arg. The setter rejects out-of-range integer.
5. `postern timefix <device-id>` against the integration harness completes successfully end-to-end; the captured timestamp delivered to the setter equals the broker's signed `now` within 1 second.
6. Three new audit event types appear in handler-test captures: `time_payload_authorized` (pre-Sign) + `time_payload_issued` (post-Sign) on success (joined on `jti`); `time_payload_denied` with stable `denied_reason` on each failure path. LD-65's "exactly one audit outcome per request" invariant holds for `/ssh/time-payload` (one `*_denied`, OR the `authorized`+`issued` pair).
7. `examples/on-device/timefix/` sample includes the `setcap cap_sys_time+ep` line, the user/group creation snippet, the binary install paths, and a README that cross-references the existing `examples/on-device/sshd/` drop-in.
8. No new dependencies beyond `golang.org/x/sys` for the setter syscalls. `go-jose/v4` is already pinned (LD-62 bump to v4.1.4).
9. The unwrapped `postern timefix` works against a stock broker built from the same source tree (no wrapper, no extra config beyond the existing engineer config file).
10. **D12 cert-shape**: the real broker handler test for `/ssh/cert` with `PrincipalType=timefix` produces an `ssh-ed25519-cert-v01@openssh.com` certificate that parses back via `ssh.ParseAuthorizedKey` and asserts (a) `ValidPrincipals == ["device-<serial>-timefix"]` (the canonical serial from the test Registry mapping), (b) `ValidAfter == uint64(time.Date(1979,1,1,0,0,0,0,time.UTC).Unix())`, (c) `ValidBefore == uint64(time.Date(3000,1,1,0,0,0,0,time.UTC).Unix())`, (d) `Permissions.Extensions` is empty (no `permit-pty`), (e) `Permissions.CriticalOptions["force-command"] == "/usr/sbin/timefix-apply"` (and no other critical option), (f) `KeyId` matches the `keyID(engineer, jti)` shape the operator branch uses, (g) `Serial` matches the audit event's `cert_serial`. ## 9. Risks + watch-items

- **`go-jose/v4` API drift between sub-phases.** Per D5, production JWS construction is hand-rolled (no go-jose API surface in the production binary); go-jose is consumed only in `_test.go` files for parse-back validation. API drift risk is therefore bounded to test code, not the wire-format path. TF-A picks the parse-back shape once; later sub-phases reuse it.
- **`CertSigner` interface widening hits every wrapper.** Adding `SignRaw` is a breaking change to the exported interface that downstream wrappers compose into their broker pipeline. Mitigation: the interface is in `internal/broker` (not `pkg/`) so wrappers don't import it directly. The wrapper-visible surface (`pkg/brokerhandlers.SSHCertIssuer`) is unchanged.
- **Cross-compile for ARM/ARM64 device targets.** GoReleaser already builds linux/amd64+arm64 binaries for `postern`; the timefix binaries need the same matrix declared in `.goreleaser.yaml`. Hand off to TF-E.
- **The verifier exec'ing the setter with `syscall.Exec` replaces the verifier process.** Stderr written by the verifier before the exec stays buffered to the SSH channel; stderr from the setter goes to the same fd. Audit-log shape stays correct because the broker emits the audit event when it signs the JWS, not when the device applies it. Watch in TF-B.
- **`/etc/ssh/postern_ca.pub` format.** Verifier needs the OpenSSH-format Ed25519 public key (the same file sshd reads as `TrustedUserCAKeys`). Parser: `ssh.ParseAuthorizedKey` + downcast to the underlying ed25519 pubkey for go-jose verify. TF-B implementation detail.
